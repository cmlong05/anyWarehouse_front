# 全局居中弹窗改造设计

## 目标

将前端所有浏览器原生 `alert()`、`confirm()` 和 `prompt()` 调用替换为应用内居中弹窗，提供一致的外观、交互和可访问性，同时保持原有操作的阻塞顺序。

本次扫描基线为 55 个调用点，分布在 22 个文件：

- `alert()` 41 个
- `confirm()` 14 个
- `prompt()` 0 个

改造完成后，前端业务代码中不得再出现原生 `alert()`、`confirm()` 或 `prompt()`。

## 架构

新增一套全局弹窗基础设施，分为三个边界清晰的单元：

1. 队列管理器：只负责 FIFO 排队、当前请求和 Promise 结果，不依赖 Svelte 组件。
2. Svelte 状态适配层：把队列当前项暴露给根布局，并提供 `showAlert()`、`showConfirm()` 公共接口。
3. `DialogHost` 组件：挂载在根布局中，渲染当前弹窗，处理确认、取消、遮罩和 Escape。

所有业务页面只调用公共接口，不直接维护全局弹窗状态。

## 公共接口

```ts
showAlert(message: string, options?: AlertOptions): Promise<void>
showConfirm(message: string, options?: ConfirmOptions): Promise<boolean>
```

`AlertOptions` 包含可选的标题、图标类型和按钮文案。`ConfirmOptions` 在此基础上包含取消按钮文案和危险操作样式。

默认行为：

- `showAlert()` 是单按钮弹窗，默认按钮为“知道了”。
- `showConfirm()` 是双按钮弹窗，默认按钮为“确认”和“取消”。
- 点击遮罩或按 Escape 时，提示弹窗直接关闭，确认弹窗返回 `false`。
- 同一时间只显示一个弹窗；后续请求进入 FIFO 队列。

## 保持阻塞语义

原生弹窗会阻塞后续 JavaScript 执行。业务调用方必须保持这一顺序：

- 需要等待用户关闭提示或确认操作时使用 `await showAlert()` 或 `await showConfirm()`。
- 只用于错误通知且后续没有顺序依赖时，可以使用 `void showAlert()`。
- 表单提交、页面跳转、删除操作等流程必须等待确认结果后再继续。

这样可以避免点击确认前页面已经跳转，或连续提示互相覆盖。

## 视觉与交互

弹窗使用现有 TailwindCSS 视觉体系，覆盖层居中显示：

- 信息、成功、警告、错误使用不同图标和按钮颜色。
- 危险确认使用红色确认按钮。
- 多行消息保留换行。
- 弹窗打开时限制背景页面滚动，并将键盘焦点移到弹窗内。
- 操作执行期间由原业务页面继续维护自己的 loading 状态；全局确认弹窗只负责取得用户选择。

## 迁移范围

按业务区域分批替换：

1. 客户、销售订单、发货单、包裹和物流页面。
2. 供应商、采购订单和报价页面。
3. 物品、分类、属性和关联管理组件。
4. 容器、存储、盘点、出库和打印工具。

迁移时只改变弹窗调用方式，不改变业务流程、API 请求、状态机和数据模型。

## 错误处理

- 队列管理器在没有活动弹窗时忽略非法完成调用。
- 连续调用按入队顺序显示。
- 页面卸载不会清空全局队列；根布局在整个应用生命周期内持续承载弹窗。
- 如果调用方未等待 `showAlert()`，队列仍会独立完成，不会阻塞其他弹窗。
